## Finding-by-Finding Resolution

### IRO-013-F01 — Partially resolved

Resolved: `SchedulingService.listAuthorized` returns the complete tenant-filtered appointment set, `CapacityService` loads that set directly, and callers can no longer select or omit appointment identifiers. Overlap and daily-limit availability checks use that authoritative set.

Remaining localized defect: `remainingCapacity` subtracts `assigned.length` across all appointment dates, while the enforcement check correctly filters to the requested date. Capacity handed to scheduling or future dispatch is therefore understated when the technician has appointments on other dates.

Required correction: calculate both daily enforcement and remaining capacity from the same target-date appointment set and add a deterministic multi-date test.

### IRO-013-F02 — Partially resolved

Resolved: distinct technician skills and required skills are modeled and filtered. A supplied finite distance greater than `travelRadiusMiles` is rejected.

Remaining localized defect: travel distance is not required or validated. An omitted distance defaults to zero, and `NaN` also bypasses the comparison. Consequently the travel-radius rule remains caller-bypassable rather than enforced as a governed input boundary.

Required correction: require a finite, non-negative travel distance whenever travel-radius evaluation applies, reject missing or invalid values, and add omission, negative, and non-finite tests. Reconcile the domain model, API inventory, manifest/migration reference where applicable, rules, validator, and completion evidence with the distinct skill and governed travel fields.

### IRO-013-F03 — Partially resolved

Resolved: same-day status is derived from the requested date and injected clock, and `emergencyDailyLimit` is a profile-level emergency capacity ceiling for valid configurations.

Remaining localized defect: the numeric limits are not validated as required by IRO-013. `dailyLimit: NaN` passes the current less-than-one check, while same-day and emergency limits have no finite or range validation. Non-finite limits disable the capacity comparison and produce non-finite remaining capacity.

Required correction: require finite integer capacity values in authorized ranges, define and enforce their relationships and emergency defaults, and add zero, negative, fractional, missing, and non-finite boundary tests.

### IRO-013-F04 — Resolved

`CapacityOverrideAuthorized` now records the override identifier, effective date, additional-capacity amount, and reason in immutable hash-chained audit metadata. The direct test reads the event fields and the complete gate preserves audit-chain integrity.

### IRO-013-F05 — Substantially resolved; evidence hardening remains

Direct tests now exercise blackout, training, administrative holds, travel-radius rejection, distinct skill rejection, derived same-day behavior, emergency limits, and override evidence. The completion report and revision log reference BP-006.1.

Remaining evidence gap: partial-day exception intervals from IRO-013 remain untested, and the canonical validator was not updated to require the new BP-006.1 behavioral evidence; it still relies on the earlier test-name/source-substring checks. Documentation is also only partially reconciled: the domain/data model, API inventory, manifest, and migration reference do not explicitly describe the new distinct-skill, governed-distance, and emergency-limit fields.

Required correction: add the partial-day interval test, strengthen the validator to require the BP-006.1 evidence, and reconcile the affected documentation without expanding scope.
