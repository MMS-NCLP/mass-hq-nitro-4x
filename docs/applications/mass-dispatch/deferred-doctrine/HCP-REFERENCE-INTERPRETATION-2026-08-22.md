# MASS Dispatch — HCP Reference Interpretation

Status: REFERENCE EVIDENCE / NON-LITERAL
Date: 2026-08-22
Source: Product-owner supplied Housecall Pro captures during V1 convergence review

## Governing Interpretation

These captures are not MASS specifications and do not supersede the approved MASS Dispatch reference library. They are retained as evidence of mature field-service interaction patterns and secondary-depth expectations.

## A. Job / Work Record Reference

Useful patterns observed:

- customer identity and property/location context remain visible while working the job;
- job lifecycle controls are explicit;
- appointments, field-tech status, invoice, estimates and line items coexist around the same job object;
- service/material line items show useful commercial detail;
- location/map context can support the work record;
- terms/warranty messaging can travel with commercial documents.

MASS interpretation: Stage and job detail should preserve context and evidence without copying the HCP page. A compact map/location preview is appropriate where useful. MASS Operations and Stage remain the governing interaction model.

## B. Customer Profile Reference

Useful patterns observed:

- customer summary/contact information;
- address/location context;
- private notes;
- activity history;
- jobs, estimates, invoices, leads/relationship history;
- attachments/tags/source;
- payment and communication preference context.

MASS interpretation: customer intelligence should be a durable 360-degree record, but Pipeline remains the admin operating conveyor. Do not create duplicate workflow simply because customer history exposes the same underlying objects.

## C. Financial / Payout Reference

Useful patterns observed:

- transaction and payout status are visible and reconcilable;
- provider/payment-method context is clear;
- financial settings are separated from ordinary operational pages.

MASS interpretation: V1 requires estimate → authorization → invoice/payment → reconciliation awareness, with Square as current payment rail. General banking, financing, insurance, tax, expense accounting and payout-account administration are not automatically MASS scope.

## D. Reporting Reference

Useful patterns observed:

- mature systems expose reports across jobs, estimates, leads, invoices, payments, customer/source, technician performance, job costing, line items, discounts and time tracking;
- report discovery can be organized separately from immediate dashboards.

MASS interpretation: preserve the three-level model: Pulse for immediate operational intelligence; Role Analytics for curated decision intelligence; Reports for deeper interrogation/export. Expand report depth in V2. Open-ended custom report construction is a later horizon unless deliberately promoted.

## E. Pipeline Reference

Useful patterns observed:

- visible workflow columns;
- lead/opportunity movement;
- follow-up automation;
- conversion focus;
- configurable workflow as a mature-product capability.

MASS interpretation: MASS Pipeline is broader and more operationally integrated than a conventional sales Kanban. It governs inquiry/intake/lead/contact/estimate/authorization/scheduling/job/post-service lifecycle and conditional re-entry. V1 owns a canonical workflow. Governed workflow customization belongs to V2.

## F. Inbox / Communications Reference

This is the strongest V1-adjacent reference.

Useful patterns observed:

- unified conversation history;
- customer messages and company/system messages in the same chronology;
- images/attachments;
- job-related communication events;
- direct call/message controls;
- multiple communication audiences/categories.

MASS interpretation: Pipeline and customer objects need a coherent Communication / Media & Activity destination. Calls, SMS, email, system events, notes, attachments, future RingCentral transcripts/recordings, estimate events and authorization evidence must be linkable to the underlying object. V1 establishes the destination/foundation; V2 matures provider integration and unified communications.

## Cross-Reference Lesson: Secondary Depth

The most important general lesson is not any individual HCP page. Mature software gives interactive information a destination. Clicking a customer, job, metric, message, payment, report, card or status leads somewhere meaningful or performs a truthful action.

Therefore MASS adopts the No-Orphan-Interaction standard for V1 final refinement.

## Explicit Non-Adoptions

The captures do not authorize:

- cloning HCP navigation or layout;
- adding a separate Leads workflow that competes with Pipeline;
- resurrecting separate/duplicated Follow-Up or Pipeline pages;
- adding duplicate dashboards for admin/technician when Dashboard/Home can be role-adaptive;
- turning MASS into a banking/accounting/insurance/tax suite;
- replacing approved MASS visual references with HCP styling.

The approved MASS reference library remains the literal visual authority. These HCP captures remain comparative product references and maturity evidence.
