# MASS Dispatch — Deferred Doctrine & Reference Archive

Status: GOVERNED REFERENCE
Established: 2026-08-22
Application: MASS Dispatch / TNGD Pilot

## Purpose

This directory preserves product decisions that are intentionally outside the immediate V1 production boundary, plus the final post-overhaul refinement instructions that close known V1 gaps. Its purpose is to prevent deferred ideas from being forgotten, accidentally reintroduced into V1, or rediscovered without their original rationale.

These documents are subordinate to canonical MASS governance and approved application architecture. They are not permission to expand a production work order beyond its stated scope.

## Records

- `V1-FINAL-POST-UI-OVERHAUL-ADDENDUM.md` — final small refinement work order for Claude after the master UI overhaul. It closes interaction destinations, communications evidence, estimate/agreement authorization presentation, and related V1 seams without reopening the overhaul.
- `V2-DEFERRED-IMPLEMENTATION-DOCTRINE.md` — governed V2 maturity layer: settings architecture, communications maturation, deeper reporting, configurable workflow, integration intelligence, and measured financial/marketing intelligence.
- `V3-STRATEGIC-HORIZON-DOCTRINE.md` — higher-order intelligence, advanced automation/report construction, strategic marketing intelligence, and capabilities requiring later product-boundary decisions.
- `HCP-REFERENCE-INTERPRETATION-2026-08-22.md` — interpretation of the supplied Housecall Pro reference captures. These are reference evidence, not literal MASS specifications.

## Governing Rules

1. Approved MASS visual references remain the literal visual authority for the V1 overhaul.
2. Competitor/reference-product captures communicate useful patterns and depth, not permission to clone their information architecture.
3. Deferred items remain deferred unless promoted through a deliberate revision/work-order decision.
4. V1 shall not acquire duplicate pages merely because another product exposes a separate page for the same underlying object.
5. Pipeline, Pulse, Stage, Calendar, customer records, communications evidence, and commerce documents must preserve a coherent object/workflow model rather than become competing feature islands.
6. No visible interaction should be ornamental while implying functionality. Every interactive control must navigate, open contextual detail, execute a governed action, or explicitly explain why it is unavailable.
