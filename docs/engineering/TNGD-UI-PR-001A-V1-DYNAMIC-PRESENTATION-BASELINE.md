# TNGD-UI-PR-001A — V1 Dynamic Presentation & Operational Pulse Baseline

**Class:** Product Realization Addendum  
**Parent:** TNGD-UI-PR-001 — MASS Dispatch V1 Product Realization Pass  
**Status:** AUTHORIZED — EXECUTE WITH PRODUCT REALIZATION  
**Scope:** V1 only; no architectural expansion  
**Product:** MASS Dispatch  
**Pilot tenant:** Top Notch Garage Doors

## Purpose

Clarify the V1 presentation standard so MASS Dispatch may feel live, responsive, visually communicative and operationally aware wherever the existing frontend/data/media architecture already makes that inexpensive and safe.

This addendum does **not** authorize a new animation system, event architecture, predictive health engine, digital asset management platform, new backend domain, or launch delay. It authorizes restrained dynamic presentation and aggressive practical use of existing approved company media as part of the existing Product Realization pass.

## Naming

The primary Today command surface shall be product-labeled **Operational Pulse**. “Stage” may remain an internal/design shorthand for the presentation canvas, but the user-facing capability is Operational Pulse because it presents the current health, condition and priority of operations.

## V1 Baseline

Where naturally supported by existing state/data flows, Product Realization should include:

1. **Ambient baseline pulse.** Operational Pulse may carry the approved subtle MASS-blue breathing perimeter/presence shown by the visual reference. It must remain calm, low-cost and non-distracting.
2. **Live quantitative transitions.** Revenue, job counts, completion percentages, follow-up counts and similar values may roll/transition naturally when underlying values change rather than snapping unnecessarily.
3. **Active charts.** Existing charts/graphs should render real data and update when their underlying data/state updates. Use the visualization that best communicates the actual dataset; do not force reference-placeholder chart types onto incompatible production data.
4. **State-aware transitions.** Existing workflow/status changes may use restrained motion to communicate progression, resolution, reprioritization or changed condition.
5. **Operational Pulse context transitions.** When the primary presented condition changes, the surface may transition/flip/replace content coherently rather than behaving as a static panel. Existing priority/state logic remains authoritative.
6. **Localized card signals.** Supporting cards may use materially subtler pulse/edge/state treatment than Operational Pulse when their own data changes or condition deserves attention. Ordinary cards should remain quiet.
7. **Coherent event response where already available.** If one existing domain/state update naturally changes multiple visible components, those components should settle coherently so the cockpit reads as one operating system rather than unrelated widgets. Do not build new orchestration infrastructure solely for this effect.
8. **Resolution feedback.** Resolved conditions may receive a brief, restrained acknowledgement before the interface settles into the new state.
9. **Calm static state.** No data/state change means no gratuitous motion. Baseline breathing, if used, must be extremely subtle.
10. **Visual-first operational communication.** When useful approved media already exists, presentation should prefer showing the relevant real-world object, condition, product, project or outcome rather than reducing the same information to text alone.

## Visual Company Standard — 70–90% Target

MASS Dispatch V1 shall be a **visual company operating surface**, not a text-heavy database wearing a graphical shell.

For presentation surfaces where visual evidence is relevant and available, production should target roughly **70–90% visual communication/value**, with text serving to identify, explain, authorize, qualify and act on what is being shown. This percentage is a design-governance target, not a mechanical pixel-coverage test. It means that the dominant comprehension path should ordinarily come from the best available combination of real company media, charts, maps, status/state visualization, timelines, progress, numbers and concise supporting copy.

The 70–90% target applies where visual communication improves comprehension. It does **not** require images on surfaces where imagery adds no operational value, nor does it authorize decorative filler merely to satisfy a ratio. Forms, legal/contractual text, detailed notes, accessibility content and other inherently textual workflows remain appropriately textual.

The intended question is: **Can the operator understand most of what matters by seeing the operation before having to read through it?**

## Existing Company Media Is Production Input

Existing approved TNGD media shall be treated as **production input, not optional inspiration**. Product Realization must make reasonable use of the media already available to the project before manufacturing generic placeholders or leaving image-capable operational surfaces visually empty.

V1 should visibly realize available media categories including, where present and contextually useful:

- actual job and inspection photographs;
- garage doors, door styles, panels and installed-door imagery;
- parts, openers, accessories and product/catalog imagery;
- project photography and completed-work examples;
- before / work-performed / after sequences;
- customer/job media already associated with operational records;
- approved curated company/library imagery suitable to the presented context.

The preferred media hierarchy is:

**job-specific media → customer/project media → product/catalog media → approved curated company library → designed fallback/placeholder.**

When an actual job image exists, do not replace it with generic stock imagery merely because the generic image is easier to render. When a specific product is being recommended and approved product imagery exists, use the specific product imagery where it improves comprehension.

## Operational Pulse — Media-Aware Presentation

Operational Pulse should be capable of using the medium that best tells the operational story. It is not required to present every condition with the same card composition.

Examples of appropriate V1 composition include:

- damage/inspection condition → actual job image dominant;
- authorization/recommendation → condition media plus proposed part/product imagery where available;
- new-door/project decision → door/product/project imagery dominant;
- completed work → before / work performed / after presentation;
- scheduling/routing condition → timeline/map dominant;
- revenue/performance condition → chart/number dominant;
- payment or administrative exception → concise state/action presentation where imagery would add little value.

Production may use controlled inference to fit available media into the approved reference language. The objective is not to force every Pulse state into one template; it is to communicate the current condition through the most useful visual vocabulary already available.

## V1 Media Boundary

This addendum does **not** authorize construction of a new DAM, semantic image-recognition pipeline, automated marketing-rights system, new cloud-drive synchronization architecture, or broad media migration project.

Use existing accessible media sources, associations and delivery mechanisms where they can be integrated cleanly during Product Realization. Preserve sensible job/customer/project/product associations when already available. If a desired media behavior requires significant new ingestion, classification, rights, storage or orchestration architecture, record it for V2 and continue toward deployment.

Future automation may deepen incoming-media curation, classification, before/after pairing, product recognition, project storytelling and Studio/Growth reuse. V1's responsibility is simpler: **make the media we already possess visibly useful.**

## V1 Pulse Language

For V1, do **not** implement the full multi-stage Adaptive Ambient Dynamic Pulse intelligence model. Preserve only the simple visual language required for a coherent baseline:

- **MASS Blue = steady / alive / monitored baseline.** It is not merely a generic “success” color.
- Existing semantic warning/error colors may continue where required for accessibility and explicit local status communication.
- If an already-existing condition can safely influence the Operational Pulse treatment without new architecture, use only a restrained shift from the MASS-blue baseline toward the approved Nitro 4X red family. Avoid rainbow/traffic-light environmental status schemes.
- Pulse treatment must never obscure explicit text, icons, labels, accessibility cues or actionable status.

## Motion Rule

**Motion must communicate state, change, priority, progression, resolution or system health. Decorative animation is prohibited.**

The product should breathe because the operation is alive, not because the interface is trying to look alive.

## Reference Fidelity & Controlled Inference

Approved reference graphics remain visual-design authority, but they are not exhaustive pixel law. Preserve their hierarchy, composition, density, identity, proportions and signature elements wherever compatible with the manufactured application.

Actual working functionality, real data and relevant approved company media are authoritative for behavior and content. Where a reference contains conceptual/placeholder content, or production requirements exceed what the reference anticipated, production may infer the unresolved real estate within the established visual language.

Inference fills gaps; it does not overwrite established design decisions. Do not remove, fabricate or weaken working functionality to imitate a screenshot. Prefer the solution the reference designer would likely have produced had the final functional requirement and available real-world media been known when the reference was created.

## Stop Rule

Do not create new backend event infrastructure, predictive scoring, cross-surface motion orchestration, complex health computation, bespoke animation engines, new DAM architecture or substantial performance risk for this addendum. If an effect or media behavior is not naturally achievable during Product Realization, record it for V2 and continue toward deployment.

## Acceptance

V1 succeeds under this addendum when the live cockpit feels responsive to real operational state; Operational Pulse has a subtle recognizable baseline presence; meaningful numbers/charts/states update naturally where inexpensive; supporting cards remain quieter than the primary surface; motion remains useful and restrained; the approved reference identity remains recognizable; relevant available company media is visibly used instead of routinely ignored; media-capable Pulse states tell useful operational stories with actual job/project/product evidence where available; visual-first surfaces generally achieve the intended **70–90% visual communication/value** without decorative filler; and none of this delays deployment, harms accessibility, degrades field performance or expands V1 architecture.

**V1 directive: Make it breathe where breathing is already cheap. Make the media we already possess visibly useful. Do not build lungs—or a new media platform—before launch.**
